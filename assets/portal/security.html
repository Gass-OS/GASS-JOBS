Security at TUN-JOBS

Practical security information for candidates and employers.

Security depends on correct Supabase Auth, database Row Level Security (RLS), and Storage policies. A polished interface alone does not make data secure.

Account protection

  • Use a unique password that you do not reuse on other websites.
  • Never share your password, one-time code or password-reset link.
  • Sign out on shared devices and keep your email account secure.
  • Use the password-reset flow if you suspect that your account is compromised.

How the web portal handles files

  • Profile photos use the project's candidate-photos public bucket. A public bucket means anyone with the image URL may be able to view the image.
  • CVs use the candidate-cvs private bucket. The portal does not generate public CV URLs.
  • File uploads are limited by the interface to 5 MB for photos and 10 MB for CVs. Server-side bucket limits and policies must also enforce appropriate restrictions.

Technical boundaries

The browser uses only a Supabase publishable key. A publishable key is not a secret; it must be protected by strict RLS and Storage policies. A Supabase service-role key, database password or other privileged secret must never be placed in website JavaScript, HTML, GitHub Pages files or a mobile APK.

The portal saves profile details to the signed-in user's Supabase Auth metadata. This does not, by itself, publish searchable candidate cards or implement employer verification. Those features require server-side database tables, RLS policies and tested authorization logic.

Report a security issue

Please do not publish passwords, access tokens, private CVs or personal information in a public issue. Report suspected vulnerabilities through the repository's GitHub Security area. Include the affected page, a short description and safe reproduction steps. Do not access or download another person's private data while testing.

Responsible use

Only access accounts and files that belong to you or that you are explicitly authorized to access. Do not upload malware, impersonate another person or attempt to bypass employer verification and privacy controls.
